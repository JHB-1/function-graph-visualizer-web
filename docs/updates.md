# 자동 업데이트

0.2.0부터 공식 Pages 주소에서 시작/5분 주기/탭 복귀 시 새 빌드를 확인합니다.
`update-manifest.json`은 `schema=1`, `product=fgv`, `component=web`, semver `version`,
64자리 `build`, `files[{path,bytes,sha256}]`를 갖습니다. 빌드 도구가 배포 파일 목록을 생성합니다.

서비스 워커는 같은 배포 원본의 허용된 파일만 내려받고 파일별 크기/SHA-256을 검사합니다.
목록 100개/전체 32 MiB 상한과 제품/버전/필수 파일 검사를 통과한 빌드만 준비합니다.
명시한 해시가 없는 파일이나 다른 원본으로의 리다이렉트는 사용하지 않습니다.
현재 실행 중인 탭에 `skipWaiting`/`clients.claim`/자동 reload를 수행하지 않습니다.
전체 FGV 탭을 닫은 뒤 다시 열면 검증된 다음 버전이 적용됩니다.

새 버전 안내의 '현재 그래프 백업'은 IndexedDB 저장 성공 후 완료를 표시합니다.
진행 중인 조작, 적용 전 입력, 이전 복구 선택이 남아 있으면 먼저 처리를 요청합니다.
자동 저장 OFF에서도 명시 백업은 가능하며 다음 시작 때 복구 선택을 표시합니다.
백업 후 새 변경이 생기면 기존 미저장 종료 확인을 다시 적용합니다.
파일 저장은 별도로 계속 사용할 수 있습니다.

네트워크/해시/저장소 실패 시 열린 그래프를 유지하며 이전 캐시를 삭제하지 않습니다.
첫 도입 전의 이미 열린 페이지는 한 번 수동 갱신해야 이 기능을 받습니다.
서비스 워커/IndexedDB를 지원하지 않거나 차단한 브라우저는 일반 웹 실행 경로를 유지합니다.
MCP 위젯과 Electron의 임베디드 화면에서는 웹 업데이트를 시작하지 않습니다.
새로운 배포 코드의 기능 오류까지 해시가 보장하지는 않으며 이전 캐시와 문서 백업을 보존합니다.

검증: Windows Chrome에서 실제 HTTP 배포 응답을 바꾸어 SW waiting 상태, 자동 reload 부재,
명시 백업/복구, 잘못된 digest 거절, 저장 실패 시 현재 그래프 보존을 검사합니다.
